# 문장군 디지털 컬러북 — Project Brief

## 비전
"현장 컬러북을 넘어서는 프리미엄 디지털 경험. 영업사원의 무기이자, 고객의 선택을 돕는 온라인 쇼룸."

## 문제 정의
문장군 중문 영업팀이 무료방문실측 후 컬러를 선택하지 못한 고객(공실, 미결정자)에게
스마트스토어 쇼핑스토리 링크를 보내고 있으나, 단순 긴 이미지 나열 방식으로는
필름의 질감·분위기·시공 후 느낌을 제대로 전달하지 못해 최종 전환이 지연됨.

## 타겟 사용자
| 구분 | 누구 | 핵심 니즈 |
|------|------|-----------|
| 1차 사용자 (배포자) | 문장군 영업사원 | **메인 페이지 링크 1개**를 카톡으로 공유, 고객 설득 보조 |
| 최종 사용자 (소비자) | 중문 구매 고려 고객 | 고화질 텍스처 확인 + 실제 시공 사례 탐색 → 컬러 최종 결정 |
| 관리자 | 문장군 담당자 (사장님 본인) | 컬렉션/컬러 추가·수정, 시공 사진 업로드를 직접 수행 |

## 핵심 사용 시나리오
```
고객: "매니저님 컬러 너무 고민되서 못고르겠어요. 다시 볼 수 있는 방법 없을까요?"
영업: "네 고객님, 링크 드릴테니 거기 들어가셔서 원하시는 컬렉션 컬러 천천히 보세요~"
       → 메인 페이지 링크 1개 전송
       → 고객이 직접 컬렉션 탐색 → 컬러 상세 확인 → 최종 결정
```

## 핵심 가치 제안
"컬러 카드 리스트 → 풀스크린 텍스처 → 스크롤 애니메이션 시공 사례"로 이어지는
매거진급 프리미엄 경험 + 개발자 없이 콘텐츠를 자유롭게 관리하는 어드민 시스템.

## 기존 대안 & 차별점
| 항목 | 기존 (스마트스토어) | 디지털 컬러북 |
|------|---------------------|---------------|
| 탐색 방식 | 전체 스크롤 (모든 컬러 혼재) | 컬렉션별 분류 → 관심 컬러만 집중 탐색 |
| 비주얼 품질 | 작은 썸네일, 긴 통이미지 | 풀스크린 텍스처 + 스크롤 애니메이션 |
| 공유 방식 | 전체 페이지 링크 | **메인 링크 1개 공유** → 고객이 알아서 탐색 |
| 콘텐츠 관리 | 스마트스토어 에디터 제약 | 자체 어드민에서 자유롭게 추가/수정 |

## 컬러 컬렉션 구조 (초기 데이터)
| 컬렉션 | 컬러 수 | 특징 |
|---------|---------|------|
| 오리지널 컬러 | 8종 | 블랙, 네이비, 핑크 등 원색 계열 |
| 퍼스널 화이트 | 5종 | 화이트톤 변주 |
| 발렌 스페셜 | 3종 | 스톤 계열 질감 |
| 프리미엄 우드 | 3종 | 우드 계열 질감 |
| **합계** | **19종** | 컬렉션·컬러 모두 어드민에서 **무한 추가** 가능 |

## 컬러 상세 페이지 구성 (안)
1. **히어로 섹션** — 필름 텍스처 풀스크린 고화질 (뷰포트 100%)
2. **컬러 정보** — 컬러명, 컬렉션명, 한 줄 카피, 상세 설명
3. **시공 갤러리** — 해당 컬러로 시공된 현장 사진 (최소 5장, 스크롤 애니메이션 적용)
4. **액션 바** — 무료방문실측 예약 / 브랜드스토어 이동 (하단 고정 또는 플로팅)

## MVP 범위 (초기 버전)
### ✅ 포함
- **고객 페이지 (프론트)**
  - 모바일 퍼스트 반응형 (카톡 유입 = 99% 모바일)
  - 컬렉션별 컬러 카드 리스트 (메인)
  - 컬러 상세 페이지 (풀스크린 텍스처 + 스크롤 애니메이션 + 시공 갤러리)
  - 카카오톡 OG(Open Graph) 메타 — 메인 페이지용 (이미지는 관리자 직접 제작)
  - 하단 액션: 무료방문실측 예약 페이지 이동 / 브랜드스토어 중문 상품 이동
- **어드민 페이지 (관리자)**
  - 컬렉션 CRUD (추가/수정/삭제/순서변경)
  - 컬러 CRUD (이미지 업로드, 텍스트 편집, 시공사진 관리)
  - 초안(Draft) → 미리보기(Preview) → 공개(Published) 워크플로우
  - 간단한 로그인 인증 (1인 관리자)

### ❌ 제외 (추후 확장)
- 직접 결제/장바구니 기능
- 고객 문의/댓글 기능
- 다국어 지원
- ABS도어 라인업 (중문 완성 후 확장)

## 기술 방향
- **프론트엔드**: Next.js (SSR/SSG로 OG 메타 + SEO + 빠른 로딩)
- **백엔드/DB**: Supabase (DB + Storage + Auth 올인원)
- **이미지 저장**: Supabase Storage (고화질 원본 + WebP 변환 최적화)
- **애니메이션**: Intersection Observer 기반 스크롤 애니메이션
- **배포**: Vercel (Next.js 최적 호스팅)

## 설계 원칙
1. **모바일 퍼스트**: 카톡 유입 시나리오가 메인. 데스크탑은 보너스.
2. **카톡 미리보기 = 첫인상**: 메인 페이지 OG 최적화 (이미지는 관리자 제작).
3. **메인 링크 1개로 충분**: 고객이 알아서 탐색하는 UX. 컬러별 딥링크는 내부 라우팅용.
4. **콘텐츠 자립**: 개발자 없이 컬렉션/컬러/사진 관리가 가능해야 함.
5. **무한 확장**: 컬렉션·컬러 개수에 제한 없는 유연한 데이터 구조.
6. **퍼포먼스**: 고화질이지만 빨라야 함 — Lazy Loading, WebP, 이미지 최적화 필수.

## 리스크 & 대응
| 리스크 | 심각도 | 대응 방안 |
|--------|--------|-----------|
| 고화질 이미지 + 애니메이션 → 모바일 로딩 지연 | 🟡 중 | WebP 변환, Lazy Loading, Next.js Image 최적화 |
| 어드민 UX가 복잡하면 결국 안 씀 | 🟡 중 | 최대한 단순한 UI, 드래그앤드롭 이미지 업로드 |
| 카톡 OG 캐시로 인한 썸네일 미반영 | 🟢 저 | 카카오 캐시 초기화 API 연동 또는 가이드 제공 |

## 시공 사진 가이드 (콘텐츠 준비용)
| 항목 | 권장 사양 |
|------|-----------|
| 컬러당 시공 사진 수 | 5~8장 |
| 텍스처 메인 이미지 | 1장 (고해상도, 최소 1920x1080) |
| 시공 사진 해상도 | 최소 1200x800 |
| 파일 형식 | JPG 또는 PNG (업로드 시 WebP 자동 변환) |
| 촬영 팁 | 다양한 각도 + 조명 환경, 전체샷 + 클로즈업 혼합 |
