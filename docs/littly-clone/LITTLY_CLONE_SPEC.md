## 1. 제품 경계

### 1.1 원형 충실도

- 편집 화면의 정보 구조, 블록 생성·편집 흐름, 실시간 미리보기, 공개 렌더링을 고충실도로 재현한다.
- 유료 잠금으로 보이는 상담 페이지 관련 기능은 문장군 제품에서 제한 없이 제공한다.
- 리틀리의 코드, 로고, 아이콘 파일, 일러스트, 고유 문구와 브랜드 표현은 가져오지 않는다.

### 1.2 문장군 확정 차이

| 항목 | 판정 | 결정 |
|---|---|---|
| 페이지 계층 | INTENTIONAL | 데이터에 `parent_id`, `sort_order`를 두고 쇼룸 방식의 탐색 계층을 지원한다. |
| 공개 URL | INTENTIONAL | 계층과 무관한 평면 canonical URL `/l/{slug}`를 유지한다. |
| 노드 진입 | INTENTIONAL | 모든 노드는 부모를 거치지 않아도 독립 페이지로 온전히 열린다. |
| 계층 UI | DEFERRED | 1차 리틀리 편집기 복제 후 쇼룸 노드 관리 경험을 적용한다. |
| 영상 제공자 | EXTENSION | 원형 확인 후 Instagram, Naver Clip 등을 제공자별 렌더러로 확장한다. |

## 2. 전역 편집기

### 2.1 데스크톱 구조 — VERIFIED

- 1690×916 뷰포트 관찰 기준으로 왼쪽 페이지 레일, 중앙 휴대폰 미리보기, 오른쪽 편집 패널의 3열 구조다.
- 상단 전역 탭은 `페이지`, `디자인`, `분석`, `관리`, `마케팅` 5개다.
- 편집 패널의 아코디언은 한 번에 하나만 펼쳐진다.
- 프로필에는 ON/OFF, 레이아웃 4종, 이미지, 대표문구, 상세문구, 글자 크기 소·중·대가 있다.
- 중앙 미리보기와 실제 공개 페이지는 DOM 구조와 렌더링 결과가 강하게 일치한다. 구현에서는 하나의 공유 렌더러를 사용한다.

### 2.2 블록 선택기 — VERIFIED

총 24종을 확인했다.

- 콘텐츠: 단일 링크, 그룹 링크, SNS, 동영상, 텍스트, 갤러리, 여백, 음악, 지도, 파일 공유
- 커뮤니케이션: 문의, 일정, 고객정보, 연락처, 공지, 검색, 방명록
- 수익화: 국내 판매, 글로벌 판매, 후원, 예약, 광고, 멤버십
- 외부 연동: 네이버 스마트스토어

### 2.3 공통 블록 동작 — VERIFIED

- 블록 메뉴 `…`: 복사, 페이지 이동, 삭제.
- 복사는 새 불변 ID를 가진 블록을 즉시 생성하고 공개 페이지에도 반영한다.
- 이동은 중첩된 페이지 목록에서 목적지를 고른다.
- 블록 전체 삭제는 “삭제하면 복구할 수 없습니다” 취지의 확인 모달을 거친다.
- 불완전한 필수 입력 블록은 편집기에서 오류를 보이지만 공개 페이지에는 나타나지 않는다.
- 공개 데스크톱은 휴대폰 프레임 안 약 473px 콘텐츠 폭, 모바일 390px에서는 전체 폭으로 렌더링됐다.

## 3. 콘텐츠 블록

### 3.1 단일 링크 — RECONSTRUCTED

#### 필드와 생성

- ON/OFF, 강조, 예약, 필수 URL, 이미지, 필수 제목, 레이아웃 3종, 추가 옵션.
- 빈 상태에는 “단일 링크 블록이 생성될 위치입니다.” 취지의 자리표시자와 필수 입력 오류가 보이며 공개에는 숨겨진다.
- URL을 먼저 입력하면 제목 필수 오류로 전환된다.
- URL blur 뒤 Open Graph 정보를 비동기로 가져오며, 가져오기 완료 전 사용자가 적은 제목을 덮어쓸 수 있다. 메타데이터 완료 후 다시 입력한 제목은 유지됐다.
- 메타데이터 처리가 끝난 뒤에는 제목 입력 중 포커스가 남아 있어도 자동 저장됐다.

#### 렌더링과 옵션

- 이미지가 없으면 소·중·대 레이아웃 모두 약 307.6×50.5px, 반경 14px의 같은 카드로 수렴했다.
- 옵션에는 강조 태그, AI 태그 생성, 판매가, 정가가 있다.
- 강조를 켜면 일반 카드와 함께 페이지 하단 고정 CTA가 생긴다. 다른 강조 블록을 대체한다는 안내가 있으며 다시 누르면 조용히 해제된다.
- 공개 고정 CTA 관찰값: `z-index: 10`, 데스크톱 폭 약 435px, 자식 높이 54px, 하단 여유 50px.
- 예약 모달에는 ON/OFF, 공개/숨김/공개 후 숨김 방식과 날짜·시간이 있다. 과거 시각은 비활성화된다.
- 예약 모달의 X는 취소가 아니며 변경값이 자동 저장됐다.
- 블록 OFF 즉시 미리보기와 공개 페이지에서 제거되고, ON 복구도 즉시 반영됐다.

#### 구현 수용 조건

- 메타데이터 응답과 사용자 수정의 경합에서 사용자의 마지막 수정이 사라지지 않아야 한다.
- 편집 미리보기와 공개 페이지는 같은 렌더러를 사용해야 한다.
- 강조 CTA는 콘텐츠 스크롤과 독립된 고정 영역으로 동작해야 한다.

### 3.2 그룹 링크 — RECONSTRUCTED

#### 필드와 생성

- 선택적 상단 문구와 하나 이상의 하위 링크가 필요하다.
- 하위 링크 모달: 필수 URL, 필수 제목, 판매가, 정가, 필수 이미지, 태그, AI 태그.
- URL blur 시 메타데이터를 가져오며 YouTube URL에서 제목과 이미지를 만들었다.
- 새 하위 항목은 목록 맨 위에 삽입됐다.

#### 레이아웃

| 모드 | 공개 페이지 관찰값 |
|---|---|
| 기본 | 약 395×100px 카드가 세로로 누적 |
| 2열 | 약 192.5×224.5px; 가격 정보가 많으면 높이 증가 |
| 3열 | 약 125×153px; 가격 정보가 많으면 높이 증가 |
| 캐러셀 1 | 약 224×256px 가로 스크롤 |
| 캐러셀 2 | 약 145×177px 가로 스크롤 |

#### 상호작용

- 활성 항목 5개에서 접기 옵션을 쓰면 처음 4개와 `더보기`가 보이고, 누르면 전체와 `접기`가 보인다.
- 활성 항목이 4개이면 접기 컨트롤이 나타나지 않았다.
- 하위 행을 누르면 수정 모달이 열린다.
- 하위 ON/OFF는 공개 페이지에 즉시 반영된다.
- 하위 휴지통은 별도 확인 없이 즉시 삭제한다.
- 드래그 정렬은 접근성 알림으로 위치 이동을 안내하고 약 1.3초 뒤 공개 순서에 반영됐다.
- 정가 1,500원, 판매가 1,000원 입력에서 33% 할인으로 표시됐다.

### 3.3 SNS — RECONSTRUCTED

- 빈 블록은 공개에 숨겨진다.
- 기본 행은 Instagram과 전화이며 같은 채널을 중복 추가할 수 있다.
- 검색 가능한 채널 선택기에서 167개를 확인했다. `SNS 추가 요청`은 외부 Tally 링크다.
- 전화 국가 코드 선택기는 243개 항목이었다.
- Instagram의 `example` 입력은 `https://www.instagram.com/example`로 정규화됐다.
- 전화 `01012345678`은 `tel:01012345678`로 렌더링됐다.
- YouTube 채널 URL은 blur 후 직접 외부 링크가 됐다.
- 공개 페이지는 채널을 아이콘 행으로 렌더링한다.
- 예약은 있으나 강조 옵션은 없다.
- 일부 URL 변경은 blur 뒤 공개에 반영됐다.

### 3.4 동영상 — RECONSTRUCTED

#### 제공자와 검증

- 입력 자리표시자가 공식 지원 범위를 `유튜브, 비메오, 틱톡`으로 명시한다.
- YouTube, Vimeo, TikTok URL 구문이 승인됐다.
- 테스트한 Instagram Reel과 Naver Clip URL은 `유효하지 않은 링크입니다`로 거절됐다.
- Instagram/Naver Clip 지원은 리틀리 원형이 아니라 `EXTENSION`이다.

#### 레이아웃과 플레이어

- 레이아웃은 기본 세로, 캐러셀, 2열이다. 음소거 자동재생은 기본 ON이다.
- 공개 기본: YouTube/Vimeo 각각 약 415×225px 세로 누적.
- 캐러셀: 각각 약 300×225px 가로 배열.
- 2열: 각각 약 204.5×225px 좌우 배열.
- YouTube는 커스텀 요소의 open shadow DOM 내부 iframe으로 렌더링됐다. 주요 파라미터는 `playsinline=1`, `enablejsapi=1`, `cc_load_policy=1`, `rel=0`, `modestbranding=1`이었다.
- 자동재생 OFF에서 YouTube의 `enablejsapi`가 0으로 바뀌었다.
- Vimeo는 `player.vimeo.com/video/{id}` iframe과 `playsinline=1`, `preload=metadata`, `transparent=0`을 사용했다. 자동재생 토글에 따른 URL 변화는 관찰되지 않았다.
- TikTok은 입력 승인과 편집기 재생까지 확인했으나 초기 공개 탐색에서 로드 시점이 불안정했다. 가용성/타이밍은 `PARTIAL`로 남긴다.

#### 확장 수용 조건

- 제공자별 URL 파서와 렌더러를 분리한다.
- 원본 삭제, 비공개 전환, 임베드 차단 때 깨진 빈 프레임 대신 오류/대체 링크를 보여준다.

### 3.5 텍스트 — RECONSTRUCTED

- 제목은 필수이며 상세문구만 입력한 상태는 공개에 나타나지 않는다.
- 제목과 상세문구는 관찰한 흐름에서 blur 시 저장됐다.
- 기본 공개 렌더링은 제목 H2, 상세 H3이며 줄바꿈과 공백을 보존한다.
- 레이아웃은 기본 목록과 토글 접기, 정렬은 좌·중·우, 글자 크기는 소·중·대다.
- 토글 접기는 처음 제목과 화살표만 보이고, 클릭하면 상세문구가 펼쳐진다.

### 3.6 갤러리 — RECONSTRUCTED / PARTIAL

- 이미지는 필수다.
- 숨은 파일 입력은 `image/jpeg,image/png,image/gif`, `multiple=true`였다.
- 단일 이미지 상태의 기본 레이아웃과 연결 URL, 이미지 슬라이드 토글, 이미지 비율 토글을 확인했다.
- 캐러셀, 목록, 썸네일, 자유 레이아웃은 여러 이미지가 있어야 활성화된다.
- 브라우저 파일 선택 자동화가 허용되지 않아 실제 업로드, 다중 이미지 정렬, 공개 결과를 확인하지 못했다.
- 테스트용 로컬 파일은 모두 제거했고 블록도 삭제했다.

### 3.7 여백 — RECONSTRUCTED

- 스타일: 없음(기본), 점선, 실선, 물결, 지그재그.
- 입력 범위는 0~100px로 제한됐다.
- 공개 내부 높이는 입력값보다 8px 컸다: 0→8, 25→33, 100→108.
- 공개 반영이 한 저장 주기 늦게 보이는 경우가 있어 검증 시 debounce를 기다려야 한다.
- 점선·실선은 약 0.5px, opacity 30%; 물결·지그재그는 폭 52px SVG, opacity 30%였다.

### 3.8 음악 — VERIFIED

- URL은 필수이며 입력 안내 제공자는 SoundCloud, Spotify, YouTube Music이다.
- 대표문구와 추가 음악 채널을 제공한다.
- SoundCloud 주 재생기, Spotify/YouTube Music 보조 채널, 동일 Spotify 중복, 예약, 삭제 후 데스크톱·모바일 빈 상태를 확인했다.
- 캡처는 `evidence/music/`과 `evidence/supplemental-screenshots/music-detailed/`, 현재 세션의 기본 구조는 `DIR-034`에 있다.

### 3.9 지도 — PARTIAL

- 주소는 필수이며 검색 콤보박스를 제공한다.
- 실제 주소 선택과 공개 지도 렌더링은 외부 위치 데이터 입력을 피하기 위해 실행하지 않았다.
- 증거: `DIR-035`.

### 3.10 파일 공유 — PARTIAL

- 대표문구 필수, 이미지, 상세설명, 파일 업로드 필수, `+ 파일첨부`, 추가 옵션을 제공한다.
- 실제 파일 업로드와 허용 형식·크기·다운로드는 미확인이다.
- 증거: `DIR-036`.

## 4. 커뮤니케이션 블록

- 문의목록 모달은 제목 필수, 문의 양식 생성 체크, 입력 전 확인 비활성 상태다.
