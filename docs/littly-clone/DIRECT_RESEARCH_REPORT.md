## 3. 전역 편집 경험

### 3.1 페이지 편집

- 데스크톱은 왼쪽 페이지 레일, 중앙 휴대폰 미리보기, 오른쪽 편집 패널의 3열 구조다.
- 상단 메뉴는 `페이지 / 디자인 / 분석 / 관리 / 마케팅` 순서다.
- 페이지 레일에는 설정, 페이지 추가, 홈화면, 일반 페이지 카드가 있다.
- 조사 계정은 무료 한도 `1/1` 상태여서 추가 페이지의 생성·이름변경·삭제 전체 흐름은 실행하지 않았다.
- 일반 페이지 편집 주소는 `/munjanggun.com/page1`, 공개 주소는 `/munjanggun.com/page1`이다.
- 프로필은 ON/OFF, 레이아웃 4종, 이미지, 대표문구, 상세문구, 글자 크기 소·중·대를 제공한다. 현재 기본 글자 크기는 `대`였다.

증거: `DIR-052`, `DIR-058`~`DIR-060`, 보조 캡처 `page-lifecycle/`.

### 3.2 디자인

- 유료 디자인 안내 배너와 `플랜 알아보기`, `추천 디자인 제작`이 먼저 나온다.
- 배경: 기본 팔레트, 직접 색상값, 사진 업로드.
- 버튼색: 팔레트와 직접 색상값.
- 색 적용 범위: `부분 적용` 기본 선택, `전체 적용`.
- 버튼 모양 3종과 버튼 액션 5종이 시각 선택지로 제공된다.
- 글꼴은 기본 1종과 추가 선택지, 글꼴 검색 콤보박스를 제공한다.
- 상단메뉴, 공유/구독 버튼, 로고 노출 방식을 각각 고른다.
- 직접 측정 뷰포트 1280×720에서 편집 문서는 세로 스크롤되고, 컨트롤의 위치·크기·색·폰트·반경을 JSON으로 보존했다.

### 3.3 분석

- 기본 기간 표시는 `일주일`이었다.
- 상단 핵심 지표는 페이지 뷰, 클릭 수, 클릭율이다.
- 클릭수/조회수 전환, BEST 클릭 순위, 유입 채널·국가·도시·기기, 블록별 클릭 목록을 제공한다.
- 블록 목록에는 검색과 클릭순 정렬이 있다.
- 다운로드는 현재 플랜에서 비활성화되고 업그레이드 경로가 노출된다.
- `전체보기`를 누르면 브랜드 플랜 결제 모달이 열렸다. 결제는 실행하지 않았다.
- 계정 수치와 위치 정보는 저장소 증거에서 마스킹했다.

증거: `DIR-054`, `DIR-062`~`DIR-063`, `DIR-067`~`DIR-068`.

### 3.4 관리

- 요약은 고객 정보와 매출 현황으로 나뉜다.
- 고객 정보 분류는 문의, 일정, 파일공유, 고객정보, 구독이다.
- 매출 분류는 판매, 후원, 예약, 멤버십, 광고다.
- 고객 정보 상세 모달은 분류 탭, 기간, 다운로드, 구글 시트 연동, 검색, 표를 제공한다.
- 표 열은 번호, 이름, 분류, 이메일, 휴대폰번호, 날짜/시간, 문의제목, 상세보기, 삭제다.
- 조사 계정은 고객 데이터 0건이었다. 실제 고객 행 동작은 실행하지 않았다.

증거: `DIR-055`, `DIR-064`, 보조 캡처 `global-ui/20260813-007-manage-root.jpg`.

### 3.5 마케팅

- 진입 기능은 단체 이메일, 인스타 DM 자동 발송, 준비 중인 단체 문자다.
- 단체 이메일 모달은 발송 내역 표와 `+ 새 메일 작성`을 제공한다.
- 새 메일은 받는 사람 선택부터 시작한다. 고객 분류 탭, 마케팅 수신 동의 ON/OFF, 기간, 검색, 체크박스 표가 있다.
- 선택 고객이 없으면 `선택 완료`가 비활성화된다.
- 인스타 DM 모달은 자동화 목록, `+무료 자동화 만들기`, Q&A 링크를 제공한다.
- 실제 이메일·DM·문자는 발송하지 않았고 인스타 계정도 연결하지 않았다.

증거: `DIR-056`, `DIR-065`, `DIR-066`, 보조 캡처 `global-ui/20260813-008-marketing-root.jpg`.

## 4. 공통 블록 규칙

- 새 블록은 기본 ON이며, 헤더에서 유형명·강조·예약·더보기·접기/펼치기를 조작한다.
- 실제 초록색 스위치 클릭 영역으로 ON/OFF를 검증했다. 체크 상태가 `true → false → true`로 바뀌고 공개 페이지도 `노출 → 숨김 → 재노출`됐다. 증거: `DIR-085`~`DIR-089`.
- 필수 입력이 없는 블록은 중앙 미리보기에 자리표시자와 오류가 나타나지만 공개 페이지에는 유효 콘텐츠로 노출되지 않는다.
- 더보기 메뉴는 복사, 페이지 이동, 삭제를 제공한다.
- 삭제는 복구 불가 확인 모달을 거치며, 삭제 직후뿐 아니라 새 탭 재접속으로 서버 잔여물을 다시 검사해야 한다.
- 대표 블록은 강조로 하단 고정 CTA가 될 수 있다. 강조는 페이지당 하나이며 기존 강조 블록을 대체한다.
- 예약은 공개/숨김 시점을 설정하는 공통 기능이다.
- 편집기 미리보기와 공개 페이지는 같은 렌더러를 공유해야 한다. 두 구현을 따로 만들면 즉시 어긋난다.

| 멤버십 | 대표문구·이미지·상세설명, 심플/디테일, 상품 목록, 구매자 전달메시지, 계좌, 옵션 | `PARTIAL`, `DIR-050` |
| 스마트 스토어 연동 | 실제 연결 상품 일괄 로드, 상품별 ON/OFF, 기본/2열/3열/1캐러셀/2캐러셀, 전부 나열/접기 | `VERIFIED/PARTIAL`, `DIR-051` |

## 8. 문장군 제품의 의도적 차이

다음은 리틀리 조사 결과가 아니라 대표가 확정한 제품 사양이다.

| 항목 | 판정 | 구현 규칙 |
|---|---|---|
| 페이지 트리 | `INTENTIONAL` | `parent_id`, `sort_order`로 쇼룸식 탐색 계층 지원 |
| 공개 URL | `INTENTIONAL` | 계층과 무관한 `/l/{slug}` 평면 canonical URL |
| 독립 진입 | `INTENTIONAL` | 모든 노드는 부모 없이 직접 열려도 완전한 페이지 |
| 계층 UI | `PHASE B` | 1차 리틀리 편집 경험 복제 후 쇼룸 노드 관리 UI 결합 |
| 동영상 확장 | `EXTENSION` | 원형 YouTube·Vimeo·TikTok 이후 Instagram·Naver Clip 제공자 추가 |
| 유료 잠금 | `INTENTIONAL` | 문장군 내부 사용에서 페이지·디자인·분석·마케팅 제한을 제거 |

## 9. 안전상 실행하지 않은 항목

- 실제 고객 정보 제출, 문의 발송, 방명록 작성
- 이메일·문자·인스타 DM 발송
- Instagram 계정 연결
- 수익계좌 등록, 판매자 등록, 결제, 후원, 예약 구매
- 실제 파일·영상·갤러리 이미지 업로드
- 실제 고객 데이터의 상세보기·삭제·다운로드

이 항목은 UI 구조는 조사했지만 외부 상태와 개인정보를 바꾸므로 `PARTIAL`로 남긴다. 구현 시에는 문장군 자체 테스트 계정과 더미 저장소에서 별도 검증한다.

## 10. 최종 원상복구

- 테스트용 `page1` 편집기: 블록 자리표시자 0개
- 테스트용 공개 `page1`: 테스트 문자열 0개
- 홈 편집기와 공개 홈: 테스트 문자열·빈 갤러리·공지 잔여물 0개
- 홈의 기존 무료방문실측 상담, 문장군 스토어, 스마트스토어 블록 유지
- 조사용 인앱 브라우저 탭: 0개

증거: `DIR-090`~`DIR-094`.

## 11. 구현에 바로 적용할 구조

1. `Page`는 불변 ID, 평면 slug, 선택적 `parent_id`, `sort_order`를 가진다.
2. `Block`은 불변 ID, type, order, enabled, schedule, highlight, type별 payload를 가진다.
3. 편집기 미리보기와 공개 페이지는 **같은 Block Renderer Registry**를 사용한다.
4. 블록별 편집 폼만 분리하고 공통 헤더, ON/OFF, 강조, 예약, 더보기, 삭제 확인은 공통 컴포넌트로 둔다.
5. YouTube·Vimeo·TikTok·SoundCloud·Spotify·YouTube Music·Instagram·Naver Clip은 제공자별 URL 파서와 렌더러로 분리한다.
6. 분석 화면은 나중에 만들더라도 첫 공개부터 page ID와 block ID를 안정적으로 유지하고 최소 조회·클릭 이벤트를 수집할 수 있게 한다.
7. 외부 콘텐츠가 삭제·비공개·임베드 차단되면 빈 프레임 대신 오류 상태와 원본 링크 대체 표시를 제공한다.

이 보고서와 원시 증거가 1차 구현의 기준이며, 화면을 임의로 개선하는 작업은 고충실도 복제 통과 뒤 별도 단계에서 한다.
