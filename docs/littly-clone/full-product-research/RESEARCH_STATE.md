## 비차단 미확인 묶음

Chrome 파일 선택기에서 `fileChooser.setFiles`가 `code -32000 / Not allowed`로 거부됐다. Codex의 Chrome 업로드 권한을 `항상 허용`로 바꾼 뒤에도 같은 오류를 직접 재현했다. 이 조사는 여기서 종료하며 다음 세 블록은 `NON_BLOCKING_UNVERIFIED`로 남긴다.

클립보드 이미지 붙여넣기 우회도 시험했지만 합성 fixture가 아니라 사용자의 기존 클립보드가 열려 적용 전에 즉시 취소하고 블록을 삭제했다. 이 경로는 안전하지 않으므로 재시도하지 않는다.

1. 갤러리: 다중 이미지의 실제 5개 레이아웃·정렬·공개 결과.
2. 그룹 링크: 필수 이미지가 있는 다중 링크의 5개 레이아웃·접기·정렬·공개 결과.
3. 파일공유: 실제 업로드·정렬·공개·다운로드 결과.

이 세 항목의 빈 편집 폼, 필수값, 옵션과 레이아웃 종류는 이미 확인했다. 문장군 업로더와 저장소는 독립 구현 대상이므로 리틀리 업로드 성공 증거가 프로토타입 제작의 선행 조건은 아니다. 필요하면 구현물과 대조할 수 있는 단계에서만 선택적으로 다시 확인한다.

## 다음 단계: 실제 동작 프로토타입

- 데이터: `page(id, slug, parent_id, sort_order, published)`와 `block(id, type, order, enabled, payload)`.
- URL: 계층과 분리된 평면 `/l/{slug}`. 모든 노드는 독립 진입 가능.
- 렌더링: 편집기 미리보기와 공개 페이지가 같은 렌더러를 사용.
- 편집기 셸: 좌측 페이지 레일, 중앙 모바일 미리보기, 우측 편집 패널, 상단 5개 탭.
- 7개 블록: 프로필, 단일링크, 그룹링크, 텍스트, 갤러리, 동영상, 파일공유.
- 공통 동작: ON/OFF, 정렬, 복사, 삭제 확인.
- 디자인 최소 제어: 배경색, 버튼색, 폰트.
- 분석: 대시보드 없이 페이지 조회와 블록 클릭 이벤트만 기록.

관리·마케팅의 실제 기능, 수익화·예약·방명록·검색·멤버십·광고와 분석 대시보드는 이 프로토타입에서 만들지 않는다. 상단 탭 자리는 리틀리 셸 대조를 위해 유지하되 비대상 화면임을 명확히 표시한다. 이 프로토타입을 대표가 직접 확인하기 전에는 본 제작 범위를 확대하지 않는다.
