# 링크 페이지 트리·네비게이션·디자인 스튜디오 V2 설계

작성일: 2026-08-14
상태: 사용자 검토 대기
대상: `/link-pages`, `/l/{slug}`

## 1. 목표

리틀리의 검증된 편집 흐름을 기준으로 유지하면서 문장군 전용 확장을 명확히 분리한다.

- 페이지가 수백 개가 되어도 찾고 접고 이동하기 쉬운 관리용 트리를 제공한다.
- 부모·자식 관계가 고객 공개 네비게이션으로 자동 노출되지 않게 한다.
- 페이지를 만들 때 상단 네비게이션 페이지인지 자식 페이지인지 먼저 선택한다.
- 단일 링크, 그룹 링크, 갤러리 이미지가 외부 URL뿐 아니라 내부 페이지를 안정적으로 가리킬 수 있게 한다.
- 리틀리 디자인 탭의 구성과 즉시 미리보기 경험을 복원하고, 문장군 검수 테마를 이용한 추천 디자인 기능을 강화한다.
- 기존 브라우저 저장 데이터의 page/block/item/asset ID와 slug 별칭을 손실 없이 보존한다.

## 2. 비교한 접근과 결정

### 접근 A: 리틀리 구조만 충실히 복제

기존 썸네일 레일과 자동 `홈화면 / 페이지` 메뉴를 유지한다. 원본 충실도는 높지만 페이지가 많아질수록 관리가 어려우며 트리 관계와 공개 노출이 섞이는 문제가 남는다.

### 접근 B: 현재 레일에 들여쓰기와 접기만 추가

구현량은 작지만 72×108px 썸네일을 계속 사용하므로 수십 개만 되어도 세로 공간을 과도하게 차지한다. 깊은 단계에서는 들여쓰기 때문에 제목과 조작 영역이 부족해진다.

### 접근 C: 리틀리형 편집기와 확장형 트리 관리자를 결합

리틀리의 중앙 미리보기와 우측 편집 패널은 유지하고, 왼쪽만 문장군 트리 관리자에 맞게 확장한다. 공개 네비게이션과 관리 트리를 데이터 수준에서 분리한다.

**접근 C를 채택한다.** 이는 리틀리 복제 범위와 문장군 의도적 확장 범위를 가장 명확히 나눈다.

## 3. 왼쪽 페이지 트리

### 3.1 기본 구조

- 왼쪽 레일은 대형 썸네일 목록 대신 36~40px 높이의 촘촘한 페이지 행을 사용한다.
- 상단에는 `페이지 추가`, 검색, `전체 접기`, `선택 경로 펼치기`를 둔다.
- 부모 행에서 자식 행으로 세로선과 `└` 형태의 꺾임을 시각적으로 연결한다. 문자 기호를 화면에 출력하지 않고 CSS border로 그린다.
- 자식이 있는 페이지에는 `+ / −` 상태가 분명한 접기 버튼을 둔다.
- 각 단계는 독립적으로 접고 펼칠 수 있다.
- 선택한 페이지의 모든 조상은 자동으로 펼쳐져 현재 위치를 잃지 않게 한다.
- 페이지명은 말줄임 처리하되 hover와 focus에서 전체 이름을 제공한다.
- 편집·복사·삭제는 행의 hover/focus 액션으로 제공해 기본 화면의 밀도를 낮춘다.

### 3.2 대량 페이지 대응

- 부모별 자식 인덱스를 한 번 생성하고 O(N) DFS로 표시한다. 행마다 전체 페이지 배열을 다시 검색하지 않는다.
- 접힌 하위 트리는 DOM에 렌더하지 않는다.
- 검색 결과는 일치 페이지와 그 조상 경로만 보여준다.
- 200~300개 페이지에서도 마지막 노드 선택, 접기, 다시 열기와 새로고침이 가능해야 한다.
- 데스크톱 레일은 넓이를 확보하고, 좁은 화면에서는 별도 drawer로 연다. 공개 고객 페이지에는 이 트리 UI가 나타나지 않는다.

### 3.3 접근성

- 중첩 `tree / treeitem / group` 구조를 사용한다.
- 각 부모는 `aria-expanded`, 각 행은 `aria-level`, 선택 행은 `aria-selected`를 제공한다.
- 키보드의 위·아래 이동, 좌·우 접기/펼치기, Enter 선택을 지원한다.

접힘 상태는 콘텐츠 데이터가 아니라 편집기 UI 상태로 별도 저장한다. 접기 동작은 `parentId`, `sortOrder`, `selectedPageId`를 변경하지 않는다.

## 4. 페이지 유형과 공개 네비게이션

`페이지 추가`의 첫 단계에서 다음 두 유형 중 하나를 선택한다.

```ts
type LinkPageRole = 'navigation' | 'child'
```

### 네비게이션 페이지

- 부모가 없는 최상위 페이지다.
- published 상태이면 공개 상단 메뉴의 실제 항목으로 노출된다.
- 같은 유형 페이지끼리 정렬한 순서가 상단 메뉴 순서가 된다.
- 홈을 포함한 각 페이지는 독립 URL로 직접 열 수 있다.

### 자식 페이지

- 생성 과정에서 부모 페이지를 반드시 선택한다.
- 트리에는 부모 아래 표시되지만 공개 상단 메뉴에는 자동 노출되지 않는다.
- 공개 이동은 내부 페이지 목적지를 가진 링크·이미지 블록을 통해 구성한다.
- 자식도 독립 URL로 직접 열 수 있다.

페이지 설정에서 유형을 바꿀 수 있다. 자식으로 바꿀 때는 부모 선택이 필수이고, 네비게이션 페이지로 바꾸면 `parentId`를 `null`로 만든다. draft와 삭제된 페이지는 상단 메뉴에 노출하지 않는다. 디자인 탭의 `상단 메뉴` 설정은 네비게이션 자체를 삭제하지 않고 표시 스타일 또는 해당 페이지에서의 숨김 상태를 제어한다.

기존 v1 상태는 모든 콘텐츠를 보존하면서 `parentId === null`이면 `navigation`, 부모가 있으면 `child`로 변환한다. 따라서 기존에 부모·자식 관계만으로 끼어들던 자식 탭은 V2에서 사라진다.

## 5. 내부 페이지 이동

클릭 가능한 항목의 목적지를 다음 공통 타입으로 통일한다.

```ts
type LinkDestination =
  | { kind: 'external'; url: string }
  | { kind: 'page'; pageId: string }
```

적용 범위:

- 단일 링크
- 그룹 링크의 각 항목
- 갤러리의 각 이미지

영상 URL은 영상 소스이므로 이 타입으로 바꾸지 않는다.

편집 폼에는 `외부 주소 / 내부 페이지` 선택기를 제공한다. 블록 선택기의 `페이지 이동`은 새 블록 종류를 늘리지 않고 내부 페이지 목적지가 미리 선택된 단일 링크 프리셋으로 제공한다.

내부 목적지는 slug가 아니라 불변 page UUID를 저장한다. 렌더 시 현재 canonical slug를 계산하므로 slug를 바꿔도 링크가 끊기지 않는다. 외부 링크만 새 탭으로 열고 내부 페이지는 같은 탭에서 이동한다. 편집 미리보기에서는 실제 페이지 전환을 공용 `onNavigate(pageId)`로 처리한다.

대상 페이지를 삭제하려 할 때 참조 중인 네비게이션과 블록을 먼저 보여주고 재지정 또는 연결 제거를 요구한다. 참조를 남긴 채 삭제하지 않는다.

## 6. URL 자동 미리보기

외부 URL을 입력하면 서버 Route Handler가 제한된 시간 안에 공개 메타데이터를 읽는다.

- `og:title`, 문서 title, `og:image`, favicon 순으로 제목과 이미지를 제안한다.
- 자동 결과는 제안값일 뿐이며 사용자가 제목과 이미지를 언제든 덮어쓸 수 있다.
- 조회 중, 성공, 이미지 없음, 사이트 차단, 잘못된 URL 상태를 필드 안에서 명확히 보여준다.
- private IP, localhost, file URL, 비 HTTP(S), redirect 폭주, 과도한 응답 크기를 차단한다.
- 네이버 등 메타데이터를 주지 않거나 서버 조회를 막는 서비스에서는 수동 업로드를 그대로 제공한다.

URL을 입력할 때마다 불필요하게 요청하지 않고 debounce하며, 동일 URL 결과는 짧게 캐시한다.

## 7. 링크 카드 테두리와 강조

- 기본 링크 카드는 테두리와 outline 없이 렌더한다.
- 브라우저 주석 도구의 파란 선택선은 제품 UI가 아니므로 비교 대상에서 제외한다.
- `링크 강조`는 임의의 2px outline을 붙이지 않는다.
- 강조 표현은 디자인 탭의 버튼 액션과 연결해 상승, 눌림, 화살표, 표면 강조 같은 검수된 효과로 제공한다.
- `prefers-reduced-motion`에서는 움직임을 제거하고 색·명도 차이로 상태를 전달한다.

## 8. 디자인 스튜디오

### 8.1 리틀리 기준 구조

조사 증거의 섹션 순서와 시각 타일 방식을 기준으로 다음을 실제 동작시킨다.

1. 추천 디자인 제작
2. 배경 프리셋, 커스텀 색상, 사진 배경
3. 버튼색 프리셋, 커스텀 색상, 적용 범위
4. 버튼 모양 3종
5. 버튼 액션 5종
6. 타이포그래피 미리보기 타일
7. 상단 메뉴 스타일
8. 공유·구독 버튼 노출 방식
9. 기본 로고, 내 로고, 로고 숨김

선택 타일은 `disabled`로 상태를 표현하지 않고 radio 또는 `aria-pressed`를 사용한다. 모든 색상에는 이름과 HEX를 함께 제공한다.

### 8.2 문장군 개선: 큐레이티드 추천 디자인

완전한 임의 RGB 조합 대신 검수된 테마 레시피 중 하나를 선택한다.

예시 레시피:

- Editorial Ink
- Warm Forest
- Quiet Showroom
- Photo Focus
- Clean Consultation
- Soft Material

추천 디자인 버튼은 다음 원칙을 따른다.

- 현재와 다른 레시피를 비반복 추첨한다.
- 클릭 즉시 공용 렌더러 미리보기에 적용한다.
- 적용된 테마명과 변경 항목을 `aria-live`로 알려준다.
- 직전 상태를 보존하고 `이전 디자인으로 되돌리기`를 항상 제공한다.
- 배경, 버튼, 타이포그래피를 각각 잠가 마음에 드는 부분을 유지한 채 다시 추천받을 수 있다.
- 모든 후보는 본문 4.5:1, 큰 텍스트와 UI 경계 3:1 이상의 대비를 통과해야 한다.
- 난수는 클릭 시에만 사용하고 렌더 과정에서는 사용하지 않는다.

### 8.3 문장군 타입과 색상 원칙

- 큰 제목에만 Tmoney RoundWind를 사용한다.
- 본문과 UI는 Pretendard를 기본으로 한다.
- Ink는 주요 정보, Forest는 상담·선택·활성 상태에 사용한다.
- 커스텀 색상은 자동 글자색과 대비 결과를 함께 보여준다.
- 색상만으로 선택 상태를 전달하지 않고 테두리, 체크, 레이블을 함께 사용한다.

## 9. 데이터 모델과 마이그레이션

저장 형식을 `version: 2`로 올리고 validator보다 먼저 `migrateLinkPageState()`를 실행한다.

- 기존 단일 링크, 그룹 링크, 갤러리 URL은 추측 없이 `external` 목적지로 보존한다.
- 기존 page/block/item/asset ID, slug, slugAliases, sortOrder를 그대로 유지한다.
- 기존 root 페이지는 `navigation`, 부모가 있는 페이지는 `child`로 변환한다.
- 접힘 상태는 별도 UI 저장 키를 사용한다.
- migration은 반복 실행해도 같은 결과를 내야 한다.
- migration 실패 시 자동으로 예시 데이터로 초기화하지 않고 오류와 복구 선택을 보여준다.

페이지·블록·항목 복사에서 새 개체만 새 UUID를 받고, 기존 개체의 UUID는 유지한다.

## 10. 컴포넌트 경계

- `tree.ts`: O(N) 트리 인덱스, ancestor/descendant, 표시 노드 계산
- `PageTree.tsx`: 트리 행, 검색, 접기/펼치기, 키보드 조작
- `navigation.ts`: 공개 네비게이션과 내부 목적지 해석, 역참조 탐색
- `PageTypeSelector.tsx`: 생성 첫 단계의 네비게이션/자식 유형 선택
- `PageNavigationEditor.tsx`: 네비게이션 페이지 정렬과 상단 메뉴 표시 설정
- `LinkDestinationField.tsx`: 외부 URL/내부 페이지 공통 입력
- `theme-recipes.ts`: 검수된 테마와 추천 선택 순수 함수
- `DesignStudio.tsx`: 리틀리형 디자인 제어와 되돌리기
- `LinkPageRenderer.tsx`: 미리보기와 공개 페이지가 계속 함께 사용하는 단일 렌더러

`LinkPageStudio.tsx`에 모든 책임을 계속 추가하지 않고 위 경계로 분리한다.

## 11. 검증 기준

### 자동 검증

- 실제 v1 상태를 v2로 열어 모든 ID, slug alias, asset 참조가 보존되는지 확인한다.
- 4단계 트리의 단계별 접기, 새로고침 유지, 선택 경로 자동 펼침을 확인한다.
- 300개 페이지에서 DFS 순서, 검색, 접힌 DOM 감소와 상태 보존을 확인한다.
- navigation 페이지만 미리보기와 공개 상단 메뉴에 나타나고 child는 나타나지 않는지 확인한다.
- 내부 페이지 링크가 대상 slug 변경 뒤 새 canonical URL로 이동하는지 확인한다.
- 참조된 페이지 삭제가 차단되고 참조 위치를 알려주는지 확인한다.
- 추천 디자인 적용 뒤 theme만 바뀌고 page/block/item ID는 유지되는지 확인한다.
- URL 자동 미리보기의 성공, 이미지 없음, 차단, timeout, 수동 덮어쓰기를 확인한다.

### Chrome 시각 검증

- 사용자 선택 브라우저인 Chrome에서 1300×960 편집 화면을 확인한다.
- 원본 Littly 디자인 탭 증거와 동일 viewport 비교 이미지를 만든다.
- 390px 공개 페이지에서 가로 overflow, 카드 테두리, 내부 이동, 상단 메뉴를 확인한다.
- 트리 1단계·3단계·검색·전체 접기 상태를 캡처한다.

## 12. 이번 범위에서 유지하는 경계

- 분석·관리·마케팅의 실제 서버 기능은 이번 수정에 포함하지 않는다.
