# BLOG_CONTENT_OPERATING_ROUTINE

## 0. 목적

이 문서는 문장군 블로그를 꾸준히 발행하기 위한 운영 루틴이다.

목표는 글 수를 빠르게 늘리는 것이 아니다. 고객이 실제로 묻는 질문에 먼저 답하고, 현장 조건을 이해하게 돕고, 무료 방문실측견적 상담으로 자연스럽게 이어지는 콘텐츠 허브를 만든다.

내부적으로는 검색과 AI 답변 시스템이 이해하기 쉬운 구조를 갖추되, 공개 글과 고객 화면에는 자연스러운 고객 언어만 쓴다.

## 1. 운영 원칙

- 콘텐츠 초안은 Codex가 문장군_브랜드와 문장군블로그를 근거로 외부 작성한다.
- 관리자 화면은 승인된 원고의 CMS 관리 표면이다.
- Codex는 글을 작성하기 전에 문장군_브랜드에서 브랜드 사실, 금지표현, 현장 판단 기준을 확인하고, 문장군블로그에서 네이버 글, 카테고리, 중복 주제, 검색 성과, 발행 운영 기록을 확인한다.
- `/admin/platform/blog`에서는 AI 초안 생성이나 비밀값 설정을 제공하지 않는다. 큐, 편집, 사진 연결, 미리보기, 발행 이력 관리만 수행한다.
- 글은 제품명보다 고객 질문에서 시작한다.
- 가격, 가능 여부, 추가금, 먼지와 소음, 일정, 현장 변수처럼 상담 전 불안이 큰 주제를 우선한다.
- 발행 전에는 사람이 사실관계, 사진, 금지표현, 개인정보 노출 여부를 확인한다.
- 검색 노출, AI 인용, FAQ 리치결과를 보장한다고 표현하지 않는다.
- 고객 화면에는 내부 최적화 용어를 쓰지 않는다.
- 실제 사진이 필요한 글은 사진 없이 무리해서 발행하지 않는다.
- 사진 없는 발행은 예외다. 해결되지 않은 이미지 슬롯이 있거나 사진이 판단 근거인 글은 `needs_media`에 남긴다.
- CTA는 구매 압박이 아니라 `무료 방문실측견적 상담` 또는 `우리 집 조건 확인`으로 둔다.

## 2. 주간 발행 루틴

### 월요일: 주제 선택

1. `docs/platform/BLOG_FIRST_10_TOPICS.md`에서 이번 주 후보를 고른다.
2. 최근 상담에서 반복된 질문, 사진 보유 여부, 서비스 가능 지역, 계절 이슈를 확인한다.
3. 아래 중 하나에 해당하면 우선순위를 올린다.

- 상담 전에 자주 막히는 질문이다.
- 현장 조건 설명이 있어야 오해가 줄어든다.
- 실제 사진 또는 설명 가능한 현장 사례가 있다.
- 기존 글과 자연스럽게 이어 읽을 수 있다.

### 화요일: 초안 작성

초안은 아래 순서로 작성한다.

1. 고객 질문형 제목
2. 2-4문장의 짧은 결론
3. 판단 기준 3-5개
4. 현장에서 확인할 조건
5. 사진 또는 사진 부족 사유
6. 같이 보면 좋은 질문
7. 무료 방문실측견적 CTA

초안 단계에서는 내부 필드를 채운다.

- `category`
- `primary_keyword`
- `target_question`
- `summary_answer`
- `related_questions`
- `service_area`
- `product_type`
- `source_evidence`

### 수요일: 브랜드와 사실 검수

검수자는 아래를 확인한다.

- 문장군 브랜드 톤과 맞는가?
- 고객이 실제로 이해할 수 있는 말인가?
- 고정 가격처럼 읽히지 않는가?
- 현장 조건에 따라 달라질 수 있음을 설명했는가?
- 서비스 가능 지역과 품목이 실제 운영과 맞는가?
- 사진, 리뷰, 상담 기록, 브랜드 문서 등 근거가 있는가?
- 고객 개인정보, 상세 주소, 전화번호, 원본 상담 내용이 들어가지 않았는가?

### 목요일: 사진과 본문 연결

사진은 글을 꾸미는 장식이 아니라 판단 근거다.

사진 확인 순서:

1. 필요한 사진 유형을 정한다.
2. 사진보관함 또는 승인 가능한 현장 사진을 찾는다.
3. 얼굴, 차량번호, 동호수, 주소 단서, 창밖 위치 단서가 없는지 확인한다.
4. 블로그/홍보 사용 가능 여부를 확인한다.
5. alt와 caption을 고객 언어로 쓴다.
6. 공개 페이지에 내부 storage path나 원본 후보 정보가 노출되지 않는지 확인한다.

### 금요일: 발행과 Search Console

발행 전 최종 확인:

- 제목, slug, meta description이 있다.
- `target_question`과 `summary_answer`가 있다.
- 본문 블록과 CTA가 있다.
- 금지표현이 없다.
- 사실 확인일이 있다.
- 공개 이미지 alt가 있다.
- 미리보기에서 모바일 390px 좌우 overflow가 없다.
- `/blog/[slug]`의 metadata, canonical, JSON-LD가 본문 내용과 어긋나지 않는다.

발행 후 Search Console 루틴:

1. production URL에서 공개 글을 직접 연다.
2. `/sitemap.xml`에 공개 글이 들어갔는지 확인한다.
3. Search Console에서 production property를 연다.
4. sitemap을 제출하거나 최신 상태를 확인한다.
5. URL Inspection으로 새 글 URL을 검사한다.
6. 공개 페이지와 metadata를 확인한 뒤 색인 요청을 보낸다.
7. 아래 형식으로 결과를 기록한다.

```text
발행일:
글 URL:
Search Console property:
sitemap 확인:
URL Inspection 결과:
색인 요청 여부:
메모:
```

주의:

- 색인 요청은 검색 노출 보장이 아니다.
- Search Console API 자동화는 MVP 범위가 아니다.
- preview, admin, api, private URL은 검사하거나 색인 요청하지 않는다.

## 3. 월간 운영 루틴

한 달에 한 번 아래를 확인한다.

- 발행한 글 중 상담 질문과 잘 이어진 글이 있는가?
- 오래된 가격/일정/서비스 가능 지역 표현이 있는가?
- 사진이 부족해서 임시로 발행한 글이 있다면 보강할 수 있는가?
- 같이 보면 좋은 질문 연결이 자연스러운가?
- 중복 주제가 쌓이지 않았는가?
- 고객 화면에 내부 용어가 새어 나가지 않았는가?

수정이 필요한 글은 새 글처럼 다시 발행하지 않는다. 기존 글을 업데이트하고, 수정일과 사실 확인일을 갱신한다.

## 4. 카테고리별 템플릿

### `case_study` 시공사례

목적: 실제 현장 조건과 선택 이유를 보여준다.

필수 구조:

1. 어떤 집에서 어떤 고민이 있었는지
2. 시공 전 확인한 조건
3. 선택한 제품과 이유
4. 시공 후 달라진 점
5. 비슷한 집에서 확인할 점
6. 무료 방문실측견적 CTA

사진 기준:

- 실제 Before 또는 After 사진이 없으면 발행하지 않는다.
- 대표 이미지는 실제 시공 결과를 보여줘야 한다.
- 고객명, 상세 주소, 동호수, 차량번호, 얼굴은 노출하지 않는다.

### `product_guide` 제품 가이드

목적: 제품 선택 기준을 쉽게 설명한다.

필수 구조:

1. 고객 질문
2. 짧은 결론
3. 선택지가 나뉘는 기준
4. 현장에서 확인해야 하는 조건
5. 우리 집에 맞게 고르는 방법
6. 관련 질문과 CTA

사진 기준:

- 제품 디테일, 색상, 유리, 레일 등 설명 사진을 우선한다.
- 사진이 없으면 이미지 슬롯 없는 예외 발행으로만 검토하고, 제품 종류를 오해하게 만드는 대체 이미지는 쓰지 않는다.

### `customer_qa` 고객 Q&A

목적: 상담 전에 많이 묻는 질문에 직접 답한다.

필수 구조:

1. 질문형 제목
2. 2-4문장 답변
3. 가능한 경우와 어려운 경우
4. 실측 때 확인할 항목
5. 관련 질문
6. CTA

사진 기준:

- 사진이 없으면 이미지 슬롯 없는 예외 발행으로만 검토한다.
- 단, 설치 가능 여부를 판단하는 글이면 신발장, 스위치, 단차 같은 조건 사진이 있으면 우선 보강한다.
- 사진이 없으면 이미지 슬롯 없는 예외 발행으로만 검토하고, 실제 현장 판단 사례처럼 쓰지 않는다.

### `field_knowhow` 현장 노하우

목적: 현장에서 판단이 갈리는 조건을 설명한다.

필수 구조:

1. 왜 이 조건이 중요한지
2. 문제가 되는 경우
3. 현장에서 확인하는 기준
4. 선택 가능한 해결 방향
5. 고객이 미리 준비할 것
6. CTA

사진 기준:

- 조건 사진이 있으면 강하게 권장한다.
- 사진 없이 예외 발행할 때는 일반 설명으로만 쓰고, 판단을 단정하지 않는다.

### `price_guide` 가격/견적 가이드

목적: 고정 가격 대신 견적이 달라지는 이유를 설명한다.

필수 구조:

1. 가격이 궁금한 고객 질문
2. 집마다 견적이 달라지는 이유
3. 가격에 영향을 주는 조건
4. 추가 확인이 필요한 상황
5. 무료 방문실측견적으로 확인하는 이유
6. CTA

사진 기준:

- 사진이 핵심 근거가 아니면 이미지 슬롯 없는 예외 발행으로 검토할 수 있다.
- 특정 금액을 단정하거나 최저가처럼 보이는 썸네일은 쓰지 않는다.

### `area_guide` 지역/서비스 안내

목적: 실제 서비스 지역과 방문실측 흐름을 설명한다.

필수 구조:

1. 지역 고객이 궁금해하는 질문
2. 서비스 가능 여부와 확인 방식
3. 방문실측 때 보는 항목
4. 지역별 일정/운영 조건이 있다면 정확히 설명
5. 신청 전 준비할 것
6. CTA

사진 기준:

- 지역을 특정할 때 상세 주소나 고객 위치 단서를 노출하지 않는다.
- 지역 이미지를 억지로 쓰지 않는다. 실제 시공 사진이 없으면 글 구조와 CTA로 충분하다.

## 5. AEO 질문형 제목 규칙

내부 목적은 검색과 AI 답변 시스템이 글의 질문과 답을 이해하기 쉽게 만드는 것이다. 공개 제목은 고객이 자연스럽게 묻는 말이어야 한다.

좋은 제목:

- `중문 가격은 왜 집마다 달라질까?`
- `신발장이 있으면 중문 설치가 어려울까?`
- `화장실문 교체, 문짝만 바꿔도 될까?`
- `살면서 중문 시공해도 괜찮을까?`

피할 제목:

- `중문 AEO 최적화 가이드`
- `동탄 중문 검색 노출 전략`
- `문장군 지식 아카이브`
- `최저가 중문 시공 완벽 정리`

규칙:

- 제목은 한 가지 질문에 답한다.
- `target_question`은 제목보다 조금 더 실제 상담 질문처럼 써도 된다.
- `summary_answer`는 결론을 먼저 말하고, 조건에 따라 달라지는 부분을 덧붙인다.
- 숫자와 가격은 근거가 있을 때만 쓰고, 고정 약속처럼 보이면 쓰지 않는다.
- `완벽`, `무조건`, `최저가`, `100%` 같은 단정형 제목을 쓰지 않는다.

## 6. 공개 화면 금지어와 대체어

아래 단어는 공개 글, 블로그 UI, CTA, 카드 라벨에 쓰지 않는다.

| 금지 표현 | 대체 표현 |
|---|---|
| AEO | 질문에 바로 답하는 글 |
| GEO | 지역/서비스 안내 |
| LLMO | 고객 질문 중심 안내 |
| 콘텐츠 그래프 | 이어 읽기 |
| 지식 아카이브 | 블로그, 안내 글, 같이 보면 좋은 질문 |
| 검색 노출 보장 | 쓰지 않음 |
| FAQ 리치결과 보장 | 쓰지 않음 |
| public bucket / private bucket | 쓰지 않음 |
| approved / usage_status | 쓰지 않음 |

고객 화면 권장 표현:

- 같이 보면 좋은 질문
- 비슷한 현장 조건
- 같은 제품군 글
- 우리 집 조건 확인하기
- 무료 방문실측견적 상담
- 실측 전에 보면 좋은 조건

## 7. 브랜드와 톤 금지 체크

발행 전 아래 표현은 제거하거나 다시 쓴다.

- 최저가 보장
- No.1
- 고객만족 100%
- 무조건 가능
- 절대 추가금 없음
- 최고급
- 업계 최고
- 보양 작업 후 청소
- 효과적입니다
- 결론적으로
- 이처럼
- 근거 없는 통계
- 경쟁사 비방
- 실제 운영과 맞지 않는 지역/일정/서비스 표현

가격 표현 규칙:

- 고정 금액처럼 보이는 문장은 쓰지 않는다.
- 가격이 달라지는 이유를 조건 중심으로 설명한다.
- 최종 견적은 무료 방문실측견적으로 확인한다고 안내한다.

가능 여부 표현 규칙:

- `가능합니다`보다 `확인이 필요합니다`, `현장 조건에 따라 달라질 수 있습니다`를 우선한다.
- 불가능한 지역이나 품목을 가능하다고 쓰지 않는다.
- 필요한 경우 `사진만으로는 판단이 어렵습니다`라고 쓴다.

## 8. 사진 없는 글 발행 기준

사진 없는 발행은 기본값이 아니라 예외다.

사진 없이도 예외 발행을 검토할 수 있는 글:

- 고객 Q&A
- 가격/견적 가이드
- 일부 제품 선택 가이드
- 일부 지역/서비스 안내

예외 발행 조건:

- 글 안에 해결되지 않은 이미지 슬롯이 없다.
- 사진이 핵심 판단 근거가 아니다.
- 글 상태에 `사진 부족 사유`를 남겼다.
- 대표 이미지가 없을 때 목록 카드가 실제 시공사례처럼 보이지 않는다.
- 실제 사진이 확보되면 보강할 업데이트 후보로 표시했다.

사진 없이 발행하면 안 되는 글:

- 시공사례
- Before/After 비교가 핵심인 글
- 특정 현장 조건을 사진으로 확인해야 하는 글
- 제품 색상, 유리, 레일 디테일을 직접 보여줘야 하는 글

아래 중 하나라도 해당하면 발행하지 않고 `needs_media`에 남긴다.

- 이미지 슬롯이 있는데 연결 사진이 없다.
- 현장 조건을 실제 사진처럼 설명하고 있다.
- 시공사례, Before/After, 제품 디테일 확인 글이다.
- 사진 없음을 숨기기 위해 일반 이미지나 AI 생성 시공 이미지를 쓰려 한다.

사진 없이 예외 발행할 때 필수 조건:

- 대표 이미지가 없어도 카드가 시공사례처럼 오해되지 않게 excerpt를 명확히 쓴다.
- 이미지가 없는 이유를 내부 검수 메모와 운영 기록에 남긴다.
- 본문에서 보지 않은 현장 상태를 본 것처럼 쓰지 않는다.
- 실제 사진이 확보되면 업데이트 후보로 표시한다.

## 9. 발행 완료 기준

한 글은 아래를 모두 만족해야 발행한다.

- 고객 질문형 제목이다.
- `summary_answer`가 2-4문장이다.
- 카테고리 템플릿을 따른다.
- 금지표현이 없다.
- 가격과 가능 여부를 단정하지 않는다.
- 사진 사용 기준을 통과했다.
- 공개 이미지 alt와 caption이 고객 언어다.
- 개인정보와 상세 위치 단서가 없다.
- CTA가 무료 방문실측견적 상담으로 이어진다.
- 관련 글 또는 관련 질문이 최소 1개 이상 있다.
- Search Console 등록 루틴을 기록할 수 있다.
