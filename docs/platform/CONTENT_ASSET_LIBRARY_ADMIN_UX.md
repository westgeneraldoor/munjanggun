# CONTENT_ASSET_LIBRARY_ADMIN_UX - 사진보관함 운영 UX

## 0. UX 원칙

사진보관함은 운영자가 파일 시스템을 관리하는 화면이 아니다.

운영자는 사진을 올리고, 찾고, 설명을 붙이고, 본문에 넣는다. storage, RLS, 변환, 공개용 파일 준비는 시스템이 맡는다.

핵심 문장:

```text
사진은 보관함에서 고르고,
본문에는 카드처럼 넣는다.
```

## 1. 메뉴와 IA

권장 메뉴명:

```text
사진보관함
```

권장 경로 후보:

```text
/admin/platform/assets
/admin/platform/media
```

최종 경로는 PR-09에서 결정한다. 운영자에게 보이는 메뉴명은 `사진보관함`으로 고정한다.

블로그 에디터에서는 별도 메뉴 이동 없이 `+ 이미지` 버튼으로 사진보관함 모달을 연다.

## 2. 사진보관함 목록 화면

### 데스크탑 레이아웃

```text
상단: 제목 / 사진 추가
필터: 검색 / 분류 / 태그 / 제품군 / 공간 / 지역 / 사용 목적
본문: 사진 그리드
우측: 선택 사진 상세 패널
```

### 모바일 레이아웃

```text
상단: 제목 / 사진 추가
검색
필터는 접이식
사진 카드 2열 또는 1열
사진 선택 시 상세 화면으로 전환
```

390px 기준에서 좌우 overflow가 없어야 한다.

### 사진 카드 정보

사진 카드:

- 썸네일
- 사진 설명 1줄
- 분류
- 태그 1-2개
- 사용 횟수
- 최근 수정일

카드 액션:

- 선택
- 편집
- 숨기기 또는 보관

블로그 에디터 모달 안에서는 카드 액션을 단순화한다.

- 선택
- 미리보기

## 3. 여러 장 업로드

### 진입

버튼:

```text
사진 추가
```

업로드 영역 문구:

```text
사진을 끌어오거나 선택해서 추가하세요.
여러 장을 한 번에 올릴 수 있습니다.
```

보조 문구:

```text
큰 사진은 웹에서 쓰기 좋게 자동으로 줄여 저장합니다.
```

### 진행 상태

파일별 상태:

- 대기 중
- 업로드 중
- 사진 정리 중
- 완료
- 다시 시도 필요

전체 상태:

```text
12장 중 9장 완료
```

실패한 파일은 나머지 성공 파일을 막지 않는다.

### 업로드 완료 후

완료 후 운영자는 바로 기본 정보를 입력할 수 있어야 한다.

빠른 일괄 입력:

- 공통 분류
- 공통 태그
- 제품군
- 공간
- 지역
- 사용 목적

개별 입력:

- 사진 설명
- 대표 태그 조정
- 블로그/홍보 사용 가능 여부

## 4. 사진 상세/편집 패널

필드:

- 사진 설명
- 분류
- 태그
- 제품군
- 공간
- 지역
- 사용 목적
- 블로그/홍보 사용 가능
- 주소나 얼굴 등 민감정보 없음

버튼:

- 저장
- 교체
- 보관

위험한 삭제는 MVP에서 기본 버튼으로 두지 않는다. 운영 실수 방지를 위해 `보관`을 우선한다.

### 문구 예시

좋은 문구:

```text
사진 설명
분류
태그
블로그/홍보 사용 가능
주소나 얼굴 등 민감정보 없음
```

피할 문구:

```text
object_path
bucket
approved
usage_status
public 승격
private 후보
```

## 5. 검색과 필터

검색 placeholder:

```text
사진 설명, 태그, 지역으로 검색
```

필터:

- 분류
- 태그
- 제품군
- 공간
- 지역
- 사용 목적
- 사용 여부

필터 chip 예:

- 중문
- 시공후
- 좁은현관
- 신발장간섭
- 블로그용
- 대표사진 후보

검색 결과 없음:

```text
조건에 맞는 사진이 없습니다.
검색어를 줄이거나 필터를 바꿔보세요.
```

## 6. 블로그 에디터 `+ 이미지` 모달

블로그 에디터에서 `+ 이미지`를 누르면 사진보관함 모달을 연다.

모달 구성:

```text
상단: 사진보관함 / 사진 추가
검색
필터
사진 그리드
하단: 선택한 사진 / 본문에 넣기
```

모달에서 가능한 일:

- 기존 사진 선택
- 새 사진 업로드
- 검색
- 필터
- 선택한 사진 확인
- 본문에 넣기

모달에서 하지 않을 일:

- public 승격
- storage path 확인
- raw DB status 변경
- 복잡한 권한 설명

## 7. 이미지 카드 삽입 UX

사진을 선택하고 `본문에 넣기`를 누르면 본문에 이미지 카드가 삽입된다.

카드 구성:

```text
[이미지 미리보기]
사진 설명 또는 캡션
[대표사진으로 사용] [교체] [삭제]
[위로] [아래로]
```

권장 동작:

- 카드 자체가 본문 블록 하나다.
- 위/아래 이동으로 위치를 바꾼다.
- 삭제는 본문에서만 제거한다. 사진보관함 원본은 삭제하지 않는다.
- 교체는 다시 사진보관함 모달을 연다.
- 대표사진으로 사용은 글 대표 이미지 역할만 바꾼다.

## 8. 본문 컴포넌트 확장 준비

사진보관함 이후 본문 컴포넌트 확장이 필요하다.

우선순위:

1. 이미지 카드
2. 링크 버튼
3. 안내 박스
4. 체크리스트
5. Before/After 묶음
6. 비교표

PR-10은 이미지 카드에 집중한다. 링크 버튼과 안내 박스는 PR-11에서 다룬다.

## 9. 운영자에게 보여주면 안 되는 내부 단어

화면 금지 단어:

- private 후보
- blog_media
- approved
- public 승격
- source_type
- usage_status
- object_path
- bucket

대체 표현:

| 내부 의미 | 운영자 표현 |
|---|---|
| private candidate | 보관된 사진 |
| approved | 블로그/홍보 사용 가능 |
| published/public media | 공개 페이지에 사용 중 |
| blog_media | 글에 넣은 사진 |
| object_path | 표시하지 않음 |
| bucket | 표시하지 않음 |
| usage_status | 사용 상태 |

## 10. 버튼/문구 예시

주요 버튼:

- 사진 추가
- 여러 장 업로드
- 본문에 넣기
- 대표사진으로 사용
- 교체
- 삭제
- 저장
- 다시 시도

상태 문구:

```text
사진을 정리하고 있습니다.
웹에서 보기 좋게 자동으로 줄여 저장합니다.
```

```text
이 사진은 아직 설명이 없습니다.
나중에 찾기 쉽도록 설명이나 태그를 추가해보세요.
```

```text
본문에서만 삭제됩니다.
사진보관함에는 계속 보관됩니다.
```

## 11. 접근성과 반응형 기준

- 390px 모바일에서 좌우 overflow 없음.
- 사진 카드의 액션 버튼은 줄바꿈되어도 겹치지 않아야 한다.
- 업로드 진행률은 색만으로 전달하지 않는다.
- 썸네일 alt는 운영자 화면에서도 의미 있게 둔다.
- 키보드 focus-visible 상태가 보여야 한다.
- 모달은 Esc로 닫히고, 닫을 때 미저장 변경이 있으면 확인한다.

## 12. 검증 기준

PR-09/PR-10 구현 후 검증할 항목:

- 사진 0건 빈 상태
- 여러 장 업로드
- 일부 업로드 실패
- 큰 사진 자동 처리 안내
- 검색 결과 없음
- 태그/분류 필터
- 사진 상세 저장
- 블로그 에디터 `+ 이미지` 모달
- 본문 이미지 카드 삽입
- 카드 위/아래 이동
- 카드 삭제 시 사진보관함 원본 유지
- 모바일 390px overflow 없음
- 운영자 화면에 금지 내부 단어 없음

## 13. 2026-07-23 사진보관함 목록 계약

- 카드는 정사각형 이미지와 한 줄 제목만 상시 표시한다.
- 카드 전체 클릭은 상세 모달을 열고, 모달은 바깥 클릭·Esc·닫기 버튼으로 닫으며 원래 카드로 포커스를 돌려준다.
- 상단 도구막대는 검색, 필터, 6종 정렬, 선택 모드, 휴지통 보기를 제공한다.
- 체크박스는 선택 모드에서만 표시한다.
- 데스크톱은 Shift 범위선택과 pointer drag 선택, 모바일은 선택 모드의 탭 다중선택을 지원한다.
- 현재 필터 결과 전체 선택과 전체 해제를 제공한다.
- 결과 카드는 48장 단위로 점진 렌더링하며, opaque 관리자 미리보기는 native lazy image를 유지한다.
- 사용처가 있는 사진의 휴지통 이동은 서버가 transaction 안에서 다시 검사하고 차단하며 사용 위치를 표시한다.
- `보관된 사진`이나 내부 `archived` 용어 대신 운영자 화면에서는 `휴지통`을 사용한다.
