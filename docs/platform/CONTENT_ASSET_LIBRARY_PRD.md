# CONTENT_ASSET_LIBRARY_PRD - 문장군 사진보관함 요구사항

## 0. 제품 정의

사진보관함은 문장군이 블로그, 시공사례, 지역 페이지, 제품 페이지, 인스타그램, 릴스, 상담 자료에 재사용할 사진 자산을 관리하는 내부 운영 도구다.

MVP의 첫 화면 연결은 블로그 에디터지만, 제품 정의는 블로그 첨부 기능이 아니다.

```text
사진보관함 = 문장군 전체 공용 사진 자산 라이브러리
```

## 1. 사용자 역할

| 역할 | 필요 |
|---|---|
| 운영자 | 사진을 업로드하고 설명, 분류, 태그를 정리한다. |
| 콘텐츠 작성자 | 글 작성 중 사진보관함에서 사진을 골라 본문에 넣는다. |
| 관리자 | 사진 사용 가능 여부, 삭제/보관, 사용 이력을 관리한다. |
| 공개 방문자 | 공개 페이지에서 최적화된 사진만 본다. |
| 서버 | 원본 보관, 변환, 썸네일, EXIF 제거, 공개용 파일 준비를 처리한다. |

MVP에서는 운영자, 콘텐츠 작성자, 관리자를 같은 administrator 권한으로 처리할 수 있다. 향후 세분화할 수 있도록 권한 경계는 문서에 남긴다.

## 2. 핵심 사용자 흐름

### 흐름 1. 사진보관함 열기

운영자는 어드민 메뉴에서 `사진보관함`을 연다.

기본 화면:

- 최근 업로드 사진
- 검색
- 분류 필터
- 태그 필터
- 제품군 필터
- 공간 필터
- 사용 목적 필터
- `사진 추가` 버튼

빈 상태:

```text
아직 보관된 사진이 없습니다.
사진을 추가하면 블로그와 시공사례에서 다시 사용할 수 있습니다.
```

### 흐름 2. 여러 장 업로드

운영자는 `사진 추가`를 눌러 여러 장을 한 번에 업로드한다.

시스템은 각 파일을 처리한다.

```text
업로드
-> 원본 보관
-> EXIF 제거
-> WebP 변환
-> 썸네일 생성
-> 용량 최적화
-> 사진보관함에 추가
```

운영자에게 보여줄 상태:

- 업로드 중
- 정리 중
- 완료
- 다시 시도 필요

운영자에게 보여주지 않을 상태:

- private
- bucket
- object_path
- transform job id

### 흐름 3. 설명/분류/태그 입력

업로드 후 운영자는 사진별 정보를 빠르게 정리한다.

필드:

- 사진 설명
- 분류
- 태그
- 제품군
- 공간
- 지역
- 사용 목적
- 블로그/홍보 사용 가능 여부

권장 분류:

- 중문
- ABS도어
- 현관문
- 몰딩
- 시공 전
- 시공 후
- 디테일
- 문제상황
- Before/After
- 블로그용
- 인스타용
- 쇼룸용

권장 태그 예:

- 3연동
- 원슬라이딩
- 화이트
- 우드톤
- 브론즈유리
- 신발장간섭
- 좁은현관
- 바닥단차
- 스위치간섭
- 동탄
- 수원
- 아이있는집

### 흐름 4. 검색/필터

운영자는 사진이 쌓였을 때 필요한 사진을 찾을 수 있어야 한다.

검색 대상:

- 사진 설명
- 분류
- 태그
- 제품군
- 공간
- 지역
- 사용 목적

예:

```text
좁은 현관
3연동 before
브론즈유리 동탄
신발장 간섭
블로그용 중문
```

### 흐름 5. 블로그 에디터에서 `+ 이미지`

콘텐츠 작성자는 블로그 에디터에서 `+ 이미지`를 누른다.

흐름:

```text
+ 이미지
-> 사진보관함 모달
-> 업로드 또는 기존 사진 선택
-> 본문에 넣기
-> 이미지 카드 삽입
```

사진보관함 모달 안에서 할 수 있는 일:

- 최근 사진 보기
- 검색
- 분류/태그 필터
- 새 사진 업로드
- 사진 선택

### 흐름 6. 이미지 카드 삽입

사진을 선택하면 본문에 이미지 카드가 들어간다.

이미지 카드에는 다음을 표시한다.

- 미리보기
- 사진 설명 또는 캡션
- 대표사진으로 사용
- 교체
- 삭제
- 위로 이동
- 아래로 이동

카드는 기존 블록형 에디터의 한 블록으로 동작한다. 작성자는 카드 위치를 움직여 원하는 문단 사이에 넣는다.

### 흐름 7. 발행 시 공개용 사진 사용

발행 시 서버는 공개 페이지에 사용할 파일을 확정한다.

MVP 호환 원칙:

- 기존 Content OS publish flow는 바로 바꾸지 않는다.
- 사진보관함에서 선택한 사진은 기존 `blog_media` 또는 bridge 구조를 통해 발행 흐름에 연결한다.
- 공개 페이지에는 공개 가능한 WebP/thumbnail 파생 파일만 사용한다.
- 원본 파일과 내부 storage path는 공개 HTML에 노출하지 않는다.

## 3. MVP 포함 범위

PR-08 이후 구현 MVP에 포함할 범위:

- 공용 사진 자산 테이블
- 원본/웹용/썸네일 파일 관계
- 여러 장 업로드
- 서버 자동 최적화
- EXIF 제거
- WebP 변환
- 썸네일 생성
- 사진 설명, 분류, 태그, 제품군, 공간, 지역, 사용 목적
- 사진보관함 목록/검색/필터
- 블로그 에디터 `+ 이미지`에서 사진 선택
- 본문 이미지 카드 삽입
- 기존 `blog_media`와의 호환 bridge
- 공개 페이지에는 최적화된 공개용 파일만 사용

## 4. MVP 제외 범위

초기 MVP에서는 만들지 않는다.

- 외부 DAM 연동
- AppSheet 사진 자동 동기화
- AI 자동 태깅
- 얼굴/번호판 자동 블러
- 이미지 저작권 자동 판정
- 고급 중복 제거 자동 병합
- 비디오 자산 관리
- 인스타 자동 발행
- 릴스 자동 생성
- 고객이 직접 사진보관함을 보는 화면
- 공개 갤러리
- 기존 `blog_media` 삭제 또는 즉시 대체

## 5. 실패/빈 상태/오류 상태

### 사진보관함 빈 상태

```text
아직 보관된 사진이 없습니다.
사진을 추가하면 블로그와 시공사례에서 다시 사용할 수 있습니다.
```

### 검색 결과 없음

```text
조건에 맞는 사진이 없습니다.
검색어를 줄이거나 분류를 바꿔보세요.
```

### 업로드 실패

```text
사진을 올리지 못했습니다.
파일 형식이나 용량을 확인한 뒤 다시 시도해주세요.
```

### 변환 실패

```text
사진 정리에 실패했습니다.
원본은 보관되었지만 웹용 사진을 다시 만들어야 합니다.
```

### 너무 큰 파일

운영자 문구:

```text
사진 용량이 큽니다. 웹에서 쓰기 좋게 줄여 저장합니다.
```

내부 처리:

- 최대 허용 원본 크기 초과 시 업로드 거부 또는 압축 전처리
- 서버 변환 한계 초과 시 실패 상태 기록

### 지원하지 않는 파일 형식

```text
지원하지 않는 사진 형식입니다.
JPG, PNG, WebP, HEIC 파일을 올려주세요.
```

공개용 파일은 WebP 또는 정책상 허용된 형식으로 변환한다.

## 6. 개인정보/홍보 사용 확인 방식

사장님 운영 전제는 "문제없는 사진만 올린다"이다. 제품은 이 전제를 존중하되, 최소한의 확인 장치는 남긴다.

운영자 화면 문구는 간단해야 한다.

권장 필드:

- `블로그/홍보 사용 가능`
- `주소나 얼굴 등 민감정보 없음`

권장 도움말:

```text
얼굴, 차량번호, 동호수, 주소 단서가 보이는 사진은 공개 콘텐츠에 쓰지 않습니다.
```

금지:

- 운영자 화면에서 `privacy_checked`, `promotion_consent_checked`, `approved` 같은 DB 필드명을 그대로 노출
- 사진 한 장마다 지나치게 긴 법무 체크리스트를 강제

서버는 발행 시 필요한 안전 조건을 다시 확인한다.

## 7. 기존 `blog_media`와의 호환 전략

기존 `blog_media`는 Content OS MVP의 발행 안전장치다.

바로 삭제하거나 대체하지 않는다.

단계별 전략:

### 단기

사진보관함에서 선택한 사진을 블로그 글에 넣을 때, 기존 발행 흐름이 이해할 수 있는 `blog_media` row를 생성하거나 연결한다.

### 중기

`blog_media`에 `content_asset_id`를 추가하거나, 별도 bridge table로 asset과 blog media를 연결한다.

### 장기

발행 흐름이 `content_assets`와 `content_asset_files`를 직접 이해하도록 개선하고, `blog_media`는 legacy compatibility layer로 축소한다.

## 8. 성공 기준

- 운영자가 사진을 여러 장 올리고 설명/분류/태그를 정리할 수 있다.
- 블로그 작성자는 `+ 이미지`만 눌러 사진보관함에서 사진을 고를 수 있다.
- 이미지 카드는 본문 중간에 들어가고 위아래로 움직일 수 있다.
- 운영자 화면에 `private`, `approved`, `public 승격`, `blog_media` 같은 내부 단어가 보이지 않는다.
- 기존 Content OS 발행 안전장치가 무너지지 않는다.
- 공개 HTML에는 원본 storage path와 민감 내부 필드가 노출되지 않는다.
