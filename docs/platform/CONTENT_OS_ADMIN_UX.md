# CONTENT_OS_ADMIN_UX - 블로그 콘텐츠 큐와 블록형 에디터

## 0. 목적

이 문서는 MVP-CONTENTOS-01의 어드민 UX를 정의한다.

문장군 콘텐츠 OS의 어드민은 글쓰기 도구가 아니라 **승인된 원고를 검수하고, 문단별 사진을 승인하고, 문장군 공식 콘텐츠로 발행하는 CMS 운영 도구**다. 원고 작성은 Codex가 중앙 문장군 브랜드 자료와 이 프로젝트의 CMS 데이터·발행 이력을 조사해 외부에서 수행한다. 별도 블로그 운영 저장소는 이 CMS의 데이터 원본이나 동기화 대상이 아니다.

기존 플랫폼 어드민 원칙을 따른다.

- 큐 중심
- 다음 행동 명확화
- 모바일/데스크탑 반응형
- 상태와 버튼 대비 확인
- 반복 업무를 빠르게 처리

## 1. IA

경로:

```text
/admin/platform/blog
/admin/platform/blog/new
/admin/platform/blog/[id]
```

메뉴명:

```text
블로그 콘텐츠
```

MVP에서는 `/admin/platform` 하위에 둔다. 콘텐츠 OS는 공개 콘텐츠를 다루지만, 승인된 원고의 검수와 발행은 플랫폼 운영 업무이기 때문이다. 메뉴 진입 후의 페이지 제목은 `블로그 콘텐츠 큐`를 유지하고, 주요 액션은 `승인 원고 등록`이다. 관리자 UI에는 AI 초안 생성 폼, 모델 설정, AI 전용 비밀값 설정을 두지 않는다.

### 승인 원고 등록

Codex가 외부에서 완성한 원고는 `/admin/platform/blog/new`에서 관리자가 구조화해 등록한다.

- 필수 입력: 제목, slug, 카테고리, SEO/AEO 필드, 본문 블록
- 등록 결과: 새 post는 명시적으로 `reviewing` 상태이며, 서버가 내부 provenance와 감사 이벤트를 자동 기록한다.
- 다음 행동: 등록 후 콘텐츠 큐와 기존 에디터에서 사진 연결, 브랜드·사실 검수, 미리보기, 발행을 진행한다.
- 입력 화면은 AI 생성, 모델 선택, 키·환경변수 설정을 제공하지 않는다.

## 2. 콘텐츠 큐

### 레이아웃

데스크탑:

```text
상단: 제목 + 주요 액션
필터: 콘텐츠 유형 / 상태 / 검색
좌측: 원고 목록
우측: 선택 글 요약 패널
```

모바일:

```text
상단: 제목 + 필터
카드 목록
카드 선택 시 상세 화면으로 이동
```

### 1차 필터

- 전체
- 시공사례
- 제품가이드
- 고객 Q&A
- 현장 노하우
- 가격/견적 가이드
- 지역/서비스 안내

### 2차 필터

- 전체
- 검토필요
- 사진부족
- 수정필요
- 발행대기
- 발행완료

### 검색

검색 대상:

- 제목
- slug
- target_question
- primary_keyword
- service_area
- product_type

### 목록 행/카드 정보

제목보다 판단 재료를 먼저 노출한다.

- 제목
- 상태 배지
- 카테고리
- 타깃 질문
- 핵심 키워드
- 지역/제품군
- 사용 사진 수
- 금지표현 경고 수
- 생성일/수정일

상태 배지:

- `검토 필요` (레거시 `ai_draft` 포함)
- `검토중`
- `사진부족`
- `발행대기`
- `발행완료`
- `보관`

위험 배지:

- `금지표현`
- `사진승인필요`
- `alt누락`
- `CTA없음`

## 3. 우측 상세 패널

데스크탑 목록에서 글을 선택하면 우측에 요약을 보여준다.

포함:

- 제목
- target question
- summary answer
- 카테고리/지역/제품군
- SEO title/meta description 상태
- 사진 슬롯 상태
- 검수 게이트 상태
- 최근 이벤트
- 버튼: `에디터 열기`, `미리보기`, `보관`

`미리보기`는 `published` 전에도 관리자 인증 상태에서만 접근 가능해야 한다.

## 4. 에디터

### 레이아웃

데스크탑:

```text
왼쪽: 문단 아웃라인
중앙: 본문 블록 에디터
오른쪽: 사진 / 검수 / SEO-AEO 패널
```

모바일:

```text
상단 탭: 본문 / 사진 / 검수 / SEO
본문은 단일 컬럼
하단 고정: 저장 / 미리보기 / 발행 요청
```

### 왼쪽 아웃라인

표시:

- H2/H3 heading
- 문단 번호
- 사진 슬롯 상태
- QA 블록 여부
- CTA 위치

클릭 시 해당 블록으로 스크롤한다.

### 중앙 본문 에디터

MVP는 복잡한 WYSIWYG가 아니라 블록형 편집이다.

블록 타입:

- Heading
- Paragraph
- Image Slot
- Link Button
- Guide Box
- Q&A
- CTA

각 문단 블록 필드:

- 본문
- 문단 의도
- 필요한 사진 유형
- 연결된 사진
- 검수 상태

이미지 슬롯:

- 대표 이미지
- Before
- After
- 제품/디테일
- 현장 조건
- 시공 과정

CTA 블록:

- 무료방문 실측견적 상담
- 네이버예약
- 브랜드스토어
- A/S 접수

MVP 기본 CTA는 무료방문 실측견적 상담이다.

PR-19 확장:

- Link Button은 공개 블로그, 관련 글, 무료방문 실측견적 같은 내부 공개 경로로만 연결한다.
- Guide Box는 안내, 알아두세요, 현장 조건, 주의 성격으로 나누되 고객 화면에는 AEO/GEO/LLMO 같은 내부 용어를 쓰지 않는다.
- 두 블록 모두 `text`와 문자열 metadata만 사용한다. 배열/객체 metadata 기반 편집은 후속 비교표/체크리스트 PR에서 별도 설계한다.

## 5. 사진 삽입 UX

사진 삽입은 "업로드"가 아니라 "문단에 맞는 사진 승인"이다.

각 이미지 슬롯에서 가능한 액션:

- 업로드
- 기존 블로그 미디어 선택
- AppSheet 후보 연결 준비
- 제거
- alt/caption 수정
- 개인정보 확인 체크
- 홍보 활용 동의 확인 체크

MVP에서는 AppSheet 자동 연동을 구현하지 않는다. 다만 UI와 데이터 모델은 `source = appsheet` 후보를 수용할 수 있게 둔다.

사진 승인 체크:

- 얼굴 없음 또는 가림 처리
- 차량번호 없음 또는 가림 처리
- 주소/동호수 단서 없음
- 창밖 위치 단서 위험 없음
- 고객 개인정보 없음
- 홍보 활용 가능 확인
- 중복 사용 이력 확인

사진이 없으면:

- `사진 없음` 또는 `사진 추후 필요`로 표시
- 글 상태를 `needs_media`로 유지
- AI 생성 시공 사진으로 대체하지 않는다.

## 6. 오른쪽 검수 패널

탭:

- 사진
- 브랜드 체크
- SEO/AEO
- 발행

### 브랜드 체크

자동 감지와 사람 확인을 같이 둔다.

체크 항목:

- 가격 단정 없음
- 최저가/최고 표현 없음
- 보양 작업 표현 없음
- 불가 지역 가능 표현 없음
- 없는 서비스 언급 없음
- 근거 없는 통계 없음
- 경쟁사 비방 없음
- A/S 기간 확인
- 서비스 가능 지역 확인
- 리뷰 수 확인
- 시공 기간 확인
- 추가금 설명 확인

### SEO/AEO

필드:

- SEO title
- meta description
- canonical URL
- primary keyword
- target question
- summary answer
- related questions
- service area
- product type
- ai citation ready

가이드:

- `summary_answer`는 2-4문장으로 쓴다.
- `target_question`은 실제 고객 질문형 문장으로 쓴다.
- 관련 질문은 FAQ rich result 보장이 아니라 Q&A 자산으로 관리한다.

### 발행 패널

발행 전 요약:

- 제목
- slug
- 공개 URL
- 카테고리
- 연결 사진 수
- 대표 이미지 상태
- 검수 통과 항목
- 미확인 항목

버튼:

- 저장
- 미리보기
- 발행 가능 상태로 변경
- 발행
- 보관

## 7. 발행 게이트

발행 버튼 비활성 조건:

- `status != ready`
- 제목/slug/meta description 누락
- target question 누락
- summary answer 누락
- 본문 블록 없음
- 금지표현 있음
- 이미지 alt 누락
- 공개 이미지 개인정보/홍보동의 미확인
- 미리보기 미확인

발행 시:

- `published_at`, `published_by` 기록
- `blog_post_events` 생성
- 공개 미디어 상태를 `published`로 전환
- sitemap 후보에 포함

## 8. 공개 미리보기

MVP 미리보기는 관리자 인증 기반으로 한다.

요구사항:

- 미발행 글은 일반 사용자가 볼 수 없다.
- 미리보기 화면 상단에 `미리보기 모드` 표시.
- 공개 페이지와 동일한 렌더링 컴포넌트를 사용한다.
- 사진이 누락된 슬롯은 관리자에게만 경고로 표시한다.

## 9. 모바일 기준

- 390px에서 좌우 overflow 없음.
- 필터는 가로 스크롤 칩 또는 접이식으로 표시.
- 블록 에디터는 단일 컬럼.
- 오른쪽 패널 기능은 탭으로 전환.
- 하단 고정 액션은 텍스트가 잘리지 않아야 한다.

## 10. 로딩, 빈 상태, 오류

- 로딩은 기존 플랫폼 어드민의 route loading 패턴을 따른다.
- 콘텐츠 큐 빈 상태는 `조건에 맞는 원고가 없습니다`처럼 운영자가 다음 행동을 이해할 수 있는 짧은 문구를 쓴다.
- 저장 실패, 이미지 업로드 실패, 이미지 승인 실패, 발행 실패는 화면 안에서 재시도 가능한 오류로 표시한다.
- 자동 저장을 도입하더라도 MVP에서는 명시적인 `저장` 버튼과 저장 상태 표시를 유지한다.
- `저장 중`, `저장됨`, `저장 실패` 상태는 에디터 상단에서 항상 확인 가능해야 한다.
- 미리보기 실패는 공개 페이지 오류처럼 보이지 않게 `미리보기 생성 실패`로 분리해 표시한다.

## 11. 권한과 공개 제한

- 관리자와 허용된 운영자만 `/admin/platform/blog`와 `/admin/platform/blog/[id]`에 접근할 수 있다.
- 검토 대상, 근거 자료, 검수 메모, 레거시 `source_prompt`, 미승인 사진은 공개 페이지에서 조회되지 않아야 한다.
- 공개 페이지는 `published` 글과 `published` 상태 미디어만 사용한다.
- preview는 관리자 인증 상태에서만 접근 가능하며 검색 노출 대상이 아니다.
- 발행 버튼은 UI에서 비활성화하더라도 server action에서 검수 게이트를 다시 확인한다.

## 12. MVP에서 만들지 않는 것

- 완전 자동 발행
- 복잡한 WYSIWYG
- 드래그앤드롭 고급 편집
- 다중 승인 워크플로우
- AI SEO 점수판
- 경쟁사 분석
- 댓글 관리
- 외부 블로그 동시 발행
- AI 생성 시공 사진

## 13. 검증

- 필터 상태별 목록 확인
- 원고 선택 시 상세 패널 표시
- 에디터에서 블록 추가/수정/삭제/정렬 가능
- 이미지 슬롯에 승인 전 이미지 연결 시 발행 불가
- 금지표현 경고가 있으면 발행 불가
- 미리보기 확인 후 발행 가능
- 모바일 390px overflow 없음
- 버튼 default/hover/active/disabled/focus-visible 대비 확인
