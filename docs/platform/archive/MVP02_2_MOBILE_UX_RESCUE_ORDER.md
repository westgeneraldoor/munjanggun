# MVP-02.2 Mobile UX Rescue 작업 오더

목표: MVP-02 / MVP-02.1에서 구현된 무료방문 실측 견적상담 신청과 플랫폼 어드민 접수 큐를 실제 고객과 운영자가 편하게 쓸 수 있는 수준으로 정리한다.

이번 작업의 기준은 “기능 추가”가 아니라 “복잡한 것을 덜어내고, 신청 흐름을 신뢰감 있게 만든다”이다.

## 절대 원칙

- 프로젝트 어디에도 이모지를 사용하지 않는다.
- 고객 신청 흐름은 모바일 390px 기준으로 먼저 설계한다.
- 화면이 AI 생성 UI처럼 보이면 실패로 본다.
- 큰 카드, 과한 장식, 과한 다크톤, 긴 안내문 복붙을 피한다.
- 고객에게 필요한 정보는 숨기지 않되, 신청을 방해하지 않게 접고 펼칠 수 있게 구성한다.
- 어드민은 모바일에서도 실제 운영자가 반복 작업할 수 있어야 한다.

## 1. 고객 무료방문 실측 견적상담 신청 페이지

대상:

- `src/app/portal/measure/new/MeasureForm.tsx`
- `src/app/portal/measure/new/measure-form.module.css`
- `src/components/platform/VisitDatePicker.tsx`
- `src/components/platform/visit-date-picker.module.css`
- `src/components/platform/DaumAddressSearch.tsx`

### 1-1. 방문 시간대 선택 제거

현재 오전/오후 방문 시간대 선택 UI를 제거한다.

변경 기준:

- 고객은 희망 방문일만 선택한다.
- DB의 `preferred_visit_time_slot`은 신규 신청에서 `null` 또는 호환 가능한 기본값 정책으로 처리한다.
- 기존 DB 제약이나 타입 때문에 null이 불가능하면, 마이그레이션 또는 서버 전송 정책을 함께 수정한다.
- 화면에서는 “방문 시간 선택” 섹션을 완전히 제거한다.

고객 안내 문구 방향:

- 정확한 방문 시간은 사전 지정이 어렵다.
- 방문 전날 오후 담당 매니저가 예상 방문 시간을 안내한다.
- 실측 상담은 지역 동선을 기준으로 순차 배정된다.
- 늦은 오후 고정 지정은 어렵다는 점을 부드럽게 안내한다.

### 1-2. 달력 축소 및 단순화

현재 달력은 모바일에서 너무 크고 깨진다. 작은 예약 달력으로 다시 만든다.

요구사항:

- 390px 모바일에서 절대 가로로 튀어나가지 않아야 한다.
- 가능한 날짜는 활성 상태, 불가능한 날짜는 비활성 상태만 명확히 보이면 된다.
- 날짜 셀 안에 긴 사유 텍스트를 넣지 않는다.
- 불가능 사유는 하단 한 줄 안내 또는 선택 시 안내 영역에서 보여준다.
- 이전/다음 달 버튼은 lucide 아이콘 또는 간결한 텍스트 버튼을 사용한다.
- 이모지/삼각형 문자 장식은 사용하지 않는다.

검증:

- 390px, 768px, 1440px에서 달력이 카드 밖으로 나가지 않아야 한다.
- 오늘 기준 min/max 접수 가능일 정책이 반영되어야 한다.
- 토요일/일요일/공휴일/수동 예외 설정이 반영되어야 한다.

### 1-3. 신청 전 안내 재구성

네이버예약 사전 안내 내용을 그대로 복붙하지 말고, 플랫폼 신청 페이지에 맞게 짧고 읽기 좋게 재구성한다.

포함할 내용:

- 견적 가능 지역
  - 수도권 상시 운영
  - 충청권은 지정 요일 운영
  - 방문 어려운 지역 안내
- 예약 접수 기준
  - 내일 방문 희망은 오늘 오후 3시 전 접수 기준
  - 오후 3시 이후는 최소 이틀 후 방문 가능
- 방문 시간 안내
  - 시간은 사전 지정이 아니라 전날 담당 매니저 안내
  - 지역 동선 기준 배정
- FAQ
  - 견적 무료 여부
  - 계약 후 시공 예상 기간
  - 시공 후 정리
  - 견적 유효기간

구성 제안:

- 신청 폼 상단에는 핵심 3줄만 노출한다.
- 자세한 안내는 `신청 전 확인사항` 접이식 영역으로 둔다.
- FAQ는 폼 하단 접이식 영역으로 둔다.

### 1-4. 주소 검색과 제출 가능 상태 수정

요구사항:

- Daum 주소 검색이 기본 흐름이다.
- 수동 입력은 보조 흐름이며, 수동 입력 시 어드민에 `수동 주소 검토 필요`가 명확히 표시되어야 한다.
- 필수 항목이 빠졌을 때 제출 버튼만 비활성화하지 말고 부족한 항목을 고객에게 알려준다.
- Playwright에서 Daum 선택 케이스와 수동 입력 케이스 모두 제출 가능해야 한다.

## 2. 관심 제품 카테고리 UI

### 2-1. 고객 선택 UI

네이버예약 옵션 리스트를 참고하되 그대로 복제하지 않는다.

요구사항:

- 다중 선택 가능.
- 품목명, 짧은 설명, 스퀘어 썸네일 이미지가 보인다.
- 체크박스는 명확하되 너무 작지 않아야 한다.
- 모바일에서 한 품목이 한 줄 카드처럼 읽혀야 한다.
- 이미지가 없을 때도 깨지지 않는 기본 placeholder를 둔다.

### 2-2. 어드민 품목 관리

현재 `식별 Key` 입력은 제거한다.

어드민 입력 필드:

- 품목명
- 품목설명
- 품목이미지

운영 방식:

- 내부 key는 화면에서 직접 입력하게 하지 않는다.
- 시스템이 품목명 기반 slug를 자동 생성하거나, DB 내부에서 자동 관리한다.
- 품목 이미지는 스퀘어 썸네일로 저장/노출한다.
- 품목 순서 변경, 노출/비노출, 수정 기능은 유지한다.

DB/Storage 확인:

- `measurement_product_categories`에 이미지 URL/path 컬럼이 없다면 마이그레이션을 추가한다.
- Supabase Storage bucket 정책이 필요하면 별도 migration 또는 설정 문서에 반영한다.

## 3. 어드민 접수 큐 단순화

대상:

- `src/app/admin/platform/page.tsx`
- `src/app/admin/platform/platform-admin.module.css`
- `src/app/admin/platform/[id]/page.tsx`
- `src/app/admin/platform/[id]/DetailClient.tsx`

### 3-1. 필터 단순화

접수 큐 필터는 아래 4개만 둔다.

- 전체
- 신규
- 접수완료
- 취소

기존 `AppSheet 대기`, `등록 완료`, `연락 완료` 같은 상태는 MVP-02.2 화면에서 제거하거나 내부 상태로만 유지한다.

### 3-2. 리스트 액션 강화

접수 건 카드/행에서 바로 처리 가능해야 한다.

필수 액션:

- 접수
- 취소

요구사항:

- 접수 건이 없을 때 빈 화면만 보이지 말고, 테스트/운영 관점에서 어떤 상태인지 명확히 표시한다.
- 접수 건이 있을 때 모바일 카드에서 고객명, 연락처, 주소, 희망 방문일, 관심 품목이 바로 보여야 한다.
- 수동 주소 입력 건은 눈에 띄게 표시한다.

## 4. 디자인 정리

### 4-1. 이모지 제거

대상 예시:

- 고객 포털 카드 아이콘
- 빈 상태 아이콘
- 어드민 설정 탭
- 달력 안내
- 수동 주소 경고

대체:

- lucide-react 아이콘
- 텍스트 라벨
- 디자인 토큰 기반 배지

### 4-2. 색상과 밀도

요구사항:

- 고객 신청 페이지는 신뢰감 있는 프리미엄 톤을 유지하되, 너무 어둡고 답답한 카드 나열을 줄인다.
- 어드민은 화이트톤 업무 UI를 유지한다.
- 카드 안에 카드가 중첩되는 구조를 피한다.
- 버튼/터치 영역은 모바일 기준 최소 40px 이상을 권장한다.

## 5. 검증 기준

필수 실행:

- `npm run lint`
- `npm run build`
- Playwright 390px 고객 신청폼 스크린샷
- Playwright 390px 어드민 접수 큐 스크린샷
- Playwright 390px 어드민 품목 설정 스크린샷
- Playwright 1440px 어드민 접수 큐 스크린샷

필수 확인:

- 고객 신청폼이 390px에서 가로로 깨지지 않는다.
- 달력은 작고 단순하게 보인다.
- 방문 시간대 선택이 없다.
- 품목 선택은 이미지/품목명/설명 기반이다.
- 품목 관리에서 식별 Key를 입력하지 않는다.
- 접수 큐 필터는 4개만 보인다.
- 접수 건 카드/행에서 접수/취소 액션이 바로 보인다.
- 이모지가 남아 있지 않다.
